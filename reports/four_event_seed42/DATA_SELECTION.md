# 四事件数据选择与验证影像名单

## 选择规则

来源为官方 xBD／xView2 的GeoTIFF六分卷，整体SHA1 `6eae3baddf86796c15638682a6432e3e6223cb39`。本次正式实验只使用归档的 `geotiffs/tier3/` 中四个事件，而不是全量19事件，也不是将六个分卷视为六个数据集。

| 项目内划分 | 事件 | 有效建筑 |
| --- | --- | ---: |
| train | joplin-tornado | 14,696 |
| train | lower-puna-volcano | 2,856 |
| val | moore-tornado | 22,372 |
| test 封存 | nepal-flooding | 41,582 |

按灾害事件划分，不在同一事件内随机拆建筑。用灾后JSON的像素坐标建筑框和损毁类别建立记录，过滤 `un-classified` 等未知标签，总计81,506栋；两组正式训练均使用全部17,552训练与22,372验证建筑，`max_train=0`、`max_val=0`。没有根据预测结果、图像美观程度或类别挑选“好看”的验证样本。测试集未做性能评估。

每栋建筑按同一正方形窗口裁剪灾前/灾后图，以灾后框中心为中心，边长 `ceil(max(框宽,框高)+2*16)`，双线性缩放到128×128。标注确定位置，当前不含自动建筑定位。B1只把灾后RGB送入模型；B2按灾前RGB、灾后RGB顺序拼为六通道。负值置零，clip到0至255并除255，无额外增强和ImageNet标准化。

## 究竟用了哪些验证影像

验证只来自 **Moore龙卷风事件**，其原始事件有227对tile；有效建筑manifest实际引用其中220对，即440幅灾前/灾后影像，共2,773,895,520字节（约2.77 GB）。原始tile数与被有效建筑引用的tile数不同，因此不能把事件所有影像数等同于验证加载文件数。

完整名单在[validation_images.csv](validation_images.csv)，每行包含：

- `relative_path`：以仓库根目录为起点的落盘路径。
- `archive_member`：官方压缩包内的准确成员路径。
- `bytes`：文件长度。
- `sha256`：文件内容校验值。

选择办法是从**原始manifest中所有split=val的建筑记录**取 `pre_image` 和 `post_image` 并去重，不是随机抽440张，也不是人工挑图。公开该名单不上传实际影像。按[复现说明](../../REPRODUCE_AND_DIAGNOSE.md)运行提取工具，可以从自己的六分卷得到相同440幅文件。

## 保持原始清单

正式训练使用的manifest SHA256为 `39b802dd01776e2f136dba3c12ba7ffb54a52eac173ca306500a45f74651a2a0`。Release复现包提供原文件，包含train/val/test全部81,506条记录。即使只评估val，也不要删行或改换行，否则checkpoint来源校验会失败。Linux/macOS读取时由加载器兼容Windows相对路径分隔符，不需要改manifest内容。

旧版仓库的 `DATASET.md` 已有四事件名称、划分和提取/清单生成步骤；本次更新补齐了正式权重、实际结果、免重训入口和精确影像名单。19事件扩大划分属于后续提案，与本次四事件复核严格区分。
