# 实验管理规则

## 三层身份

- **协议**：数据来源、划分、预处理、训练预算、指标与选优规则。
- **实验方案**：在某个协议下，为一个问题设置的对照条件。
- **运行**：某方案、某模型、某训练 seed 的一次执行，绑定实际配置与代码来源。

同一实验方案使用一张[实验卡](templates/experiment_card.md)，作为目录 README。历史卡注明“事后补录”，只引用已存在证据；未来卡在开跑前记录设计。固定模型的输入干预应标为诊断，不冒充重新训练。

## 稳定编号

| 系列 | 用途 |
| --- | --- |
| `CHECK-001` | 软件与流程检查；不是训练成绩 |
| `FE-001`、`FE-A01` | 四事件基线、相关诊断 |
| `EX-001` | 扩大实验 |
| `PERF-001`、`PERF-002` | 各环境的效率测量 |
| `WE-000`、`WE-001` 等 | 未来事件内基线与因素实验，随实际发布登记 |

编号保持稳定，目录用可理解名称；日期记录执行时间，seed 放运行层。现有已发布目录继续保留，不为了编号搬迁。

## 多 seed

数据划分身份与训练 seed 分开记录。固定划分下换训练 seed 是重复实验；更换划分是新评估条件。未来事件内划分是否确定性生成，以发布的协议为准，不能从 seed 名字推断。

在算力允许时，为主比较预先确定至少 3 个训练 seed，B1/B2 及候选方案使用配对种子。记录所有计划与实际完成种子、失败或中止；汇总单次结果、均值、样本标准差及配对差值，不挑最好 seed。只有一个结果时不报告样本标准差。训练 seed 的波动不能代表跨事件或划分不确定性。

每次运行保存完整有效配置；配置基础模板后续变化不能改写历史运行。增强随机性、数据划分算法及其随机性、训练 seed 分别说明，不能只记录一个含义不清的 seed。

## 因素与组合

每项实验指定对照编号和唯一主要改动。基线→亮度、基线→损失函数是单项检查；亮度＋损失函数另设组合实验。若连带改变实现、预算、数据或初始化，列出全部差异并限制因果解释。

提速通过同机迁移一致性验证后才考虑沿用旧基线；若改变了训练轨迹且无法建立可比性，为新流程补建匹配对照，不覆盖旧基线。

## 推荐的新结果结构

```text
reports/within_event_mm/
  baseline/
    README.md
    results.csv
    b1/seed42/               # 精选 summary / history / metadata
    b2/seed42/
  brightness/
    README.md
    results.csv
```

这是未来发布约定，示例不代表这些实验已在 main 发布。新增 seed 使用同一方案下的新运行目录；同 seed 重跑使用独立 attempt 标识并说明采用规则，不覆盖或挑选有利运行。完整权重、manifest 和备份使用 Release 等明确入口。

## 证据与最终评估

报告区分 train、val、test，以及完整样本与诊断子集；记录选优指标、实际样本量与类别支持数。val 多次用于诊断和选方案属于开发证据。预先冻结最终模型/种子/指标与评估集合，最终 test 不反向调参；项目级封存事件与事件内 test 分开定义。

实验卡是入口，报告分析结果，paper 引用证据。新增正式成果同步更新[实验索引](../reports/README.md)和[paper 证据表](../paper/evidence_map.md)；首页只列已经发布的成果。
