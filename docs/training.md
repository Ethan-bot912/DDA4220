## 提速结论的范围

GPU 报告在四事件设置下将 workers 从 0 改为 4，完整 B1/B2 合计耗时相对历史记录约 2.48 倍提速，并提供短对照和完整结果一致性记录。CPU 报告测试缓存与 worker 组合，推荐配置相对其基线约 1.78 倍；基线耗时由首轮检查点时间推算且第二轮未完成。

两份报告的机器、运行路径和对照长度不同，加速倍数不能相乘，也不能直接用于当前扩大/未来事件内流程的时间承诺。缓存读取的微基准不是完整训练加速比。CPU/GPU 结果差异的原因仍应以完整受控证据判断，不能仅凭相同 seed 就保证跨设备逐位一致。

## 后续流程采用提速前

1. 记录基线的代码版本、环境、数据划分、B1/B2 配置及实际输入。
2. 在同机同数据上做短对照，核对样本顺序、标签、张量、增强规则、loss 与指标；若存在差异，记录来源及可接受标准，不预先保证逐位一致。
3. 使用随机增强时，检查 worker、缓存和预取不会固定本应每轮变化的增强，也不会改变配对规则。
4. 检查缓存与 manifest、裁剪尺寸、上下文和预处理匹配；更换数据时重新验证。
5. 测量端到端时间、首次构建成本、冷/热缓存、内存与磁盘，并检查暂停/恢复行为。通过后在新运行记录中注明设置。

效率方案是共用实现。历史成果绑定原始版本；修改训练代码前检查冻结源文件哈希，避免破坏现有 checkpoint 的复现校验。新方案与旧结果的比较策略见[实验管理规则](experiment_management.md)。
