# 损毁等级判断失衡：类别权重对照实验方案

制定日期：2026-10-25。状态：开跑前设计，待代码实现与验收；未启动实验。

本文件是交给代码实现者的研究框架，不包含实现代码。实验卡见 [class_weight/README.md](../../reports/within_event_mm/class_weight/README.md)。

## 1. 一句话说明

在完全相同的建筑图片、模型和训练预算下，对比“按训练类别数量设置权重”与“每栋建筑的损失同等计入”，检查类别权重是否影响模型对完好、轻伤、重伤和摧毁的判断。

这是一项原因验证实验，允许得到改善、无改善或有利有弊的结果。目标不是预先认定原权重有错，也不要求 B2 胜过 B1。

### 必须保留的两个区别

第一，原标签与清单的对应关系已核查，没有发现转换贴错标签的证据；这不能证明全部源标签都正确。本次不修改标签或删除难例。

第二，expanded 与同事件实验使用相同的权重计算规则，但因训练集类别数量不同，实际权重不同：

| 设置 | 完好 | 轻伤 | 重伤 | 摧毁 |
| --- | ---: | ---: | ---: | ---: |
| expanded 原权重 | 0.233596 | 0.852526 | 0.818269 | 2.095608 |
| 同事件原权重 | 0.268856 | 0.478924 | 2.012496 | 1.239724 |
| 本次候选：等权 | 1 | 1 | 1 | 1 |

数值来自各自已保存的 summary，表中仅显示六位小数，实际执行不得抄写舍入值。原权重应从固定 train 的计数按原公式计算并核对。

同事件原权重最高的是“重伤”。取消加权可能减弱对重伤的关注，因此不能承诺重伤召回会上升。等权只表示每栋建筑的错误同等计入，不表示四类样本数量相等或四类对总损失贡献相等。

## 3. 研究问题与对照结构

研究问题：在固定同事件协议下，从原归一化逆频率权重改为等权，是否改善 B1/B2 的验证表现，以及具体改变了哪些错误？

| 条件 | B1：灾后 3 通道 | B2：灾前＋灾后 6 通道 | 用途 |
| --- | --- | --- | --- |
| A：原权重，无增强 | A-B1 | A-B2 | 匹配基线 |
| B：等权，无增强 | B-B1 | B-B2 | 本次候选 |

主要比较是 B-B1 减 A-B1、B-B2 减 A-B2；补充报告每个条件下 B2 减 B1，以及该差距的变化。不得用 B-B2 对 A-B1 的差值代替单因素结论。

已完成的亮度增强是另一项独立因素实验。本轮 A、B 均不使用亮度或其他增强；以后若研究“亮度＋等权”，另建组合实验卡，不能将它混入本次。

原权重规则：对类别 c，以 train 样本数 n_c 计算 1/n_c，再除以四个逆频率值的算术平均。沿用原交叉熵与批内加权平均语义。

候选规则：四类权重均为 1，沿用交叉熵与平均归约。实现者需保证训练损失的累计分母、日志统计与实际优化目标一致；不要在修改权重时顺带改变损失类型、学习率或采样策略。不同权重下训练 loss 数值不可直接作为谁更好的依据。

## 4. 数据与固定条件

沿用 Matthew/Moore 已冻结的按影像块分组划分，同一影像块的建筑不能跨 train/val/test。不是重新按建筑随机切分。

| 数据侧 | 样本数 | 用途 |
| --- | ---: | --- |
| train | 26,976 | 训练、统计类别数量 |
| val | 9,014 | 每轮验证、选 best、错误分析 |
| 同事件 test | 9,012 | 继续封存，本阶段不读影像、不推理、不评分 |

train 类别计数：完好 14,110，轻伤 7,921，重伤 1,885，摧毁 3,060。val 合并计数：完好 4,701，轻伤 2,653，重伤 635，摧毁 1,025。Moore 的 val 重伤只有 90 栋，单独注明不稳定。

项目级封存事件为 nepal-flooding、hurricane-florence、santa-rosa-wildfire，与本轮同事件 test 分开登记。不得为了重放 expanded 完整验证而重新读取已划入同事件 test 的图片；已有 expanded 汇总记录可继续引用。

| 项目 | 固定设置 |
| --- | --- |
| 模型 | ResNet-18，随机初始化，无预训练；B1/B2 沿用原配对初始化规则 |
| 初始状态 | 新运行从头训练；不从旧 best/last 微调；同一模型同一 seed 的 A/B 初始参数相同 |
| 输入 | 相同裁剪，128×128，context=16，像素处理沿用原协议 |
| 训练预算 | 每运行 20 轮，batch 32，float32，使用全部 train/val |
| 优化 | AdamW，lr=0.001，weight_decay=0.01，20 轮 cosine |
| 增强与采样 | 无增强，无重采样；同 seed 下各条件的样本顺序配对 |

| 中断恢复 | last 保存模型、优化器、调度器、随机状态、完整历史；只在同一冻结运行内续训 |

## 5. 历史基线、main 提速代码与可比性

远端研究计划提出先验证并行加载/缓存，再开展因素实验。当前本地历史基线使用较早的冻结实现，不能默认最新 main 与它逐项等价。

推荐执行顺序：先明确本次统一的数据读取与训练实现，再冻结 A/B 两种条件。提速是执行前的独立检查，不应只加到候选 B 上。

- 如保持历史实现语义，完成来源、数据、初始化、采样顺序、损失和恢复行为核对后，可考虑引用已有 seed42 的 A-B1/A-B2。历史来源为提交 `3ba5e61dd92f7400e1b169c1638a770e10820d03`，记录位于 `output/within_event_mm/b1/` 与 `b2/`。
- 如采用最新 main 的 workers、缓存或其他实现变更，必须先验证同机迁移可比性。仅检查“能跑”、短程分数接近或初始参数一致，不足以保证 20 轮训练轨迹一致。
- 无法充分证明旧基线可沿用时，在同一新实现下重建 A-B1/A-B2，再运行 B-B1/B-B2；新基线是新的运行，历史结果继续保留。
- 基线与候选的科学差异限定为权重；配置的名称、输出路径等记账差异单独列出。任何其他差异都需在启动前说明，不能事后把全部变化归因于权重。

因此，首轮 seed42 至少需要两次候选训练；如需匹配新实现，则需要四次训练。旧流程两模型约 10 小时仅作预算参考；四次约为两倍。提速后的耗时应根据同机验收估计，不能沿用队友其他设备的倍数。

多 seed 汇总每次值、均值、样本标准差与同 seed 配对差值。只有一个结果时不填样本标准差。缺失、中止、失败均列出，不挑最好 seed；合法中断从原 last 续训，完整重跑另建 attempt 并解释原因，不按成绩择优。

## 7. 指标与判断标准

主指标仍为合并 val Macro F1，用它选择 best；完整报告 Accuracy、Balanced Accuracy，以及合并、Matthew、Moore 的四类 precision/recall/F1/support。

预定错误检查均记录“数量 / 对应真实类别总数”与比率，A/B 使用同一范围：

| 检查项 | 目的 |
| --- | --- |
| Matthew minor→destroyed | 是否减少把轻伤严重高估 |
| Matthew major→minor、major recall | 是否减少重伤被低估，是否认出更多重伤 |
| Matthew no_damage→minor，以及完好→任意受损 | 是否减少把完好房屋误报为受损 |
| destroyed recall，以及 destroyed→no_damage/minor | 是否以漏掉真正摧毁为代价 |
| Moore 对应错误与全部分类指标 | 是否只改善 Matthew，却损害另一事件 |

配对分析应包含“旧对新错、旧错新对、都对、都错”；展示纠正和新增错误的样本，使用预先规定的分组抽样规则，不挑好看的案例。保存建筑标识以便对账。

同事件原基线参考：

| 指标 | A-B1 seed42 | A-B2 seed42 |
| --- | ---: | ---: |
| 合并 val Macro F1 | 0.662639 | 0.646984 |
| Matthew minor→destroyed / 2475 | 98 | 44 |
| Matthew major→minor / 545 | 314 | 342 |
| Matthew major recall | 0.201835 | 0.187156 |
| Matthew no_damage→minor / 812 | 557 | 480 |
| Matthew destroyed recall | 0.693617 | 0.541844 |

如果补建匹配基线，这些旧数只作历史参照，正式 A/B 差值使用新匹配基线。

预定判读：

1. 总体与关注错误同向改善：记录为该协议下的正向开发证据，再检查多 seed；单 seed 不宣称稳定或显著。
2. 轻伤判摧毁减少，但重伤/摧毁漏检增加：记录为错误取舍，不能称“解决损毁等级失衡”。
3. 总分上升但核心错误未改善：记录总体收益与机制证据不足，不将两者等同。
4. 无改善或变差：原样保留，说明本候选未获支持；不能据此排除其他权重、样本分布或视觉困难。
5. B1/B2 或两事件方向不同：分别解释，不以 B2 是否超过 B1 为成功条件。

本阶段不设无依据的“必须提高几分”或“不能下降几分”阈值。每项改善和代价都报告，下一阶段取舍在看到完整对照后讨论；若需要正式非劣效或通过门槛，须在开跑前另行确定，不能看完分数后补写。

## 8. 交给实现者的模块职责与验收要求

此处仅规定职责，不指定完整函数或编写代码。

| 模块 | 实现职责 | 验收重点 |
| --- | --- | --- |
| 配置 | 明确权重模式、实际权重、协议、seed、attempt、数据读取设置 | 未识别模式报错；配置与运行记录一致 |
| 损失与训练 | 原模式复现历史公式；等权模式按样本平均；正确累计损失 | 手算小样本可核对；权重只从 train 得到；等权不破坏日志分母 |
| 数据与隔离 | 固定 split_map、manifest 与 train/val 索引 | test 不参与训练、选优、类别计数、图像缓存或预测；缓存必须支持本轮允许范围 |
| 公平性 | 同一模型同 seed 的 A/B 配对初始化与样本顺序 | 记录初始权重与样本顺序证据；B1/B2 遵守原输入与初始化规则 |

| 评估 | 一个 best 输出总体、分事件、分类别与逐栋预测 | 指标可由混淆矩阵重算；评估范围明确为 val |
| 报告 | 读取记录生成对照、错误变化与来源 | 不覆盖历史报告，不伪造缺失运行，不顺带触发 test |

准备验收失败时先记录具体原因，修正实现后重做相关验收；不得绕过数据隔离、修改冻结划分或改科学参数来凑通过。正式运行后的代码/协议变化必须新建版本并明确影响，不直接接续旧断点。
